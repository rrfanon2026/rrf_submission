# Random Rule Forests (RRF)

This repository implements **Random Rule Forests (RRF)**, an interpretable ensemble framework for predicting startup success based on YES/NO questions generated by large language models (LLMs). It includes pipelines for data preparation, question generation, semantic filtering, optional statistical testing, and precision/recall evaluation.

## For Reviewers: Quick Start

To reproduce all paper figures and tables, open and run:

```bash
pip install -r requirements.txt
jupyter notebook notebooks/paper_reproduction.ipynb
```

The notebook reads precomputed CSV artifacts and does not require an API key or external access (it uses only pandas, numpy, and matplotlib).

Alternatively, to verify the primary model offline:

```bash
python scripts/reproduce_paper.py
```

See **[REPRODUCING_RESULTS.md](REPRODUCING_RESULTS.md)** for full reproduction options and a detailed artifact map.

## Why Precomputed Artifacts?

RRF uses LLMs for question generation and scoring. LLM outputs are **stochastic** and **API-dependent**, meaning that re-running the pipeline from scratch would produce slightly different outputs each time and requires paid API access. To ensure **exact reproducibility** of the paper results, this repository ships CSV snapshots of all LLM-generated outputs. The paper reproduction notebook reads these snapshots directly, so reviewers can reproduce every figure and table without any API calls.

## Paper Reproduction Notebook

The `notebooks/paper_reproduction.ipynb` notebook reproduces all figures and tables from the paper using precomputed artifacts stored in `precomputed/`, the alternative model folders, and `clinical_trials/results/phase_I/`. This includes:

- Main results: RRF vs elastic net vs vanilla LLM prompting
- Question-generating model comparison (GPT-4o-mini, Gemini 2.5 Pro, Claude Sonnet 4.5, GPT-5.2)
- Ablation studies: question source, similarity metric, threshold, evaluation strategy, optimisation target
- Hyperparameter sensitivity analysis
- Clinical trial (TOP Phase I) results and appendix figures

No external API access is required to run this notebook.

---

## Primary vs Ablation Policy (Anti P-Hacking Guardrail)

- Primary model config is fixed in `configs/primary_model_locked.json`.
- Headline numbers should come from `scripts/04_primary_model.py` output only.
- `scripts/05_ablation_variants.py` is secondary analysis for what-if checks and sensitivity analysis.
- Do not replace primary headline metrics with whichever ablation variant scores best.

## Primary Result Command (No API Calls)

```bash
python scripts/04_primary_model.py
```

Primary outputs:

- `precomputed/gpt_4o_mini/primary_results/primary_model_fold_metrics.csv`
- `precomputed/gpt_4o_mini/primary_results/primary_model_summary.json`
- `precomputed/gpt_4o_mini/primary_results/primary_model_manifest.json`

```bash
python scripts/05_ablation_variants.py --labels primary_reference,ablate_sort_precision
```

## Offline Reproduction Orchestrator (Recommended)

```bash
python scripts/reproduce_paper.py
```

This will:

1. Verify required files in `precomputed/`
2. Run the locked primary model (`scripts/04_primary_model.py`)
3. Write a reproducibility bundle under `repro/<run_name>/` with:
   - copied primary CSV
   - `summary.json`
   - `run_manifest.json`

To also run secondary ablations:

```bash
python scripts/reproduce_paper.py --run-secondary-ablations
```

Custom run name:

```bash
python scripts/reproduce_paper.py --run-name my_repro_run
```

Force recomputation:

```bash
python scripts/reproduce_paper.py --force
```

## Regression Tests For Precomputed Reproducibility

Before refactoring numbered scripts, run this offline regression suite to ensure
precomputed artifacts still match the baseline:

```bash
python -m unittest tests.test_precomputed_regression -v
```

Notes:

- In environments without `pandas`, the `reproduce_paper.py` smoke test is
  automatically skipped.
- For full test coverage (including smoke test), run with your project env
  (example):

```bash
/opt/homebrew/Caskroom/miniforge/base/envs/rrf313/bin/python -m unittest tests.test_precomputed_regression -v
```

If you intentionally update golden artifacts, regenerate the checksum manifest:

```bash
python tests/build_regression_manifest.py
```

This updates:

- `tests/regression_manifest.json`

## Clinical Trials Dataset

The `clinical_trials/` folder contains a second dataset application: RRF applied to clinical trial outcome prediction (TOP Phase I). The paper notebook reads results from `clinical_trials/results/phase_I/` for the clinical trials figures and tables.

- `clinical_trials/data/` — input CSVs (question-response matrices for val and test splits)
- `clinical_trials/results/phase_I/` — Phase I primary, logistic regression, and ablation results (used by the paper notebook)
- `clinical_trials/pipeline/` — scripts used to generate Phase I results
- `clinical_trials/docs/` — inventory and manifests

See `clinical_trials/README.md` for details on running the clinical trials pipeline.
